# 本清单是按 **L2 实测可用率** 筛过的, 不是抄来的列表。
# 方法: 每个源抽样 200 个节点送内核, 真的通过节点发 HTTP 请求,
#       统计"每 1000 个候选里能捞出几个可用节点"。
#       脚本: state/check-source-health.py
#
# 为什么必须用 L2 而不是 L1(TCP 可达): L1 会被 CDN 假节点骗。
# 实测有个源 L1 存活率 97%、L2 可用率 0.0% —— Cloudflare 的 IP
# 永远 TCP 可达, 但根本不是代理。
#
# 一轮实测(2026-10-08)的结果: 31 个源里只有 4 个真在干活,
# 其中 Ruk1ng001 一个贡献了绝大部分可用节点。
# 18 个源是 0.0%, 它们占了候选总量的七成 —— L1 的时间几乎全花在
# 探这些注定产出为零的节点上。
# ==================================================================

# 2026-10-08 用 GitHub API 扫了 15 个仓库、51 个候选文件, 逐个实测:
#   拉取+解析通过 45/51, 但 **L2 可用率全部低于现有最好的源**。
#   最好的新源 2.0%, 而现有 Ruk1ng001 是 69.5%。
#   有两个看着很唬人 —— 7884 个节点、L1 存活率 97% —— 实测 L2 可用率 0.0%:
#   它们 29% 是 Cloudflare/Fastly 网段, 而且 7884 个条目只覆盖 1912 个服务器
#   (4.1 倍注水)。
#
# 结论: **这个领域没有"更好的新源", 只有"更多重复的旧源"。**
# 与其扩源, 不如定期跑 state/check-source-health.py 淘汰掉已经死掉的。
